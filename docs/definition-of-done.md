# Definition of Done (DoD)

## Proyecto: EMPLEATE

La **Definition of Done (DoD)** establece los criterios que debe cumplir una funcionalidad para considerarse completamente terminada dentro del proyecto EMPLEATE.

Una historia de usuario o tarea solo se considera terminada cuando cumple todos los criterios definidos a continuación.

---

## 1. Desarrollo

* [ ] La funcionalidad fue desarrollada de acuerdo con la historia de usuario.
* [ ] El código cumple con la estructura establecida para el proyecto.
* [ ] No existen errores de sintaxis.
* [ ] Los nombres de variables, funciones y modelos son claros.
* [ ] El código se encuentra organizado y es comprensible.

---

## 2. Base de datos

* [ ] Los modelos necesarios fueron creados correctamente.
* [ ] Las relaciones entre las tablas fueron definidas correctamente.
* [ ] Las claves foráneas fueron configuradas cuando son necesarias.
* [ ] Las tablas intermedias fueron creadas cuando la relación lo requiere.
* [ ] Las migraciones fueron generadas correctamente.
* [ ] Las migraciones fueron aplicadas correctamente.

---

## 3. Funcionalidad

* [ ] La funcionalidad puede ejecutarse desde el sistema.
* [ ] Los formularios funcionan correctamente.
* [ ] Los campos obligatorios son validados.
* [ ] Los datos son almacenados correctamente en la base de datos.
* [ ] Los mensajes de error funcionan correctamente.
* [ ] Los mensajes de confirmación funcionan correctamente.

---

## 4. Pruebas

* [ ] La funcionalidad fue probada localmente.
* [ ] Se probaron los casos exitosos.
* [ ] Se probaron los casos en los que faltan datos.
* [ ] Se verificó que los datos se almacenen correctamente.
* [ ] No se presentan errores que impidan utilizar la funcionalidad.

---

## 5. Interfaz

* [ ] La interfaz es clara y fácil de utilizar.
* [ ] Los campos tienen etiquetas descriptivas.
* [ ] Los botones funcionan correctamente.
* [ ] La interfaz se visualiza correctamente en el navegador.
* [ ] No existen errores visuales que impidan utilizar la funcionalidad.

---

## 6. Git y GitHub

* [ ] Los cambios fueron realizados en una rama correspondiente a la funcionalidad.
* [ ] Se realizaron commits con mensajes claros.
* [ ] Los cambios fueron enviados al repositorio remoto.
* [ ] Se creó un Pull Request cuando corresponde.
* [ ] El código fue revisado antes de integrarse a la rama principal.
* [ ] No se subieron archivos innecesarios al repositorio.

---

## 7. Documentación

* [ ] La funcionalidad está documentada cuando es necesario.
* [ ] Se actualizaron los archivos `.md` correspondientes.
* [ ] Las instrucciones para ejecutar o probar la funcionalidad están disponibles.
* [ ] Las relaciones entre las entidades están documentadas cuando corresponde.

---

## 8. Criterio final

Una tarea se considera **DONE** únicamente cuando:

1. La funcionalidad está implementada.
2. La funcionalidad fue probada.
3. No existen errores conocidos que impidan su funcionamiento.
4. La base de datos funciona correctamente.
5. Las relaciones necesarias están configuradas.
6. Los cambios están guardados en Git.
7. Los cambios están disponibles en GitHub.
8. La documentación correspondiente está actualizada.

---

## 9. Checklist final

Antes de marcar una historia de usuario como terminada:

* [ ] Código terminado.
* [ ] Base de datos configurada.
* [ ] Relaciones verificadas.
* [ ] Pruebas realizadas.
* [ ] Interfaz verificada.
* [ ] Git actualizado.
* [ ] Pull Request realizado, si corresponde.
* [ ] Documentación actualizada.
* [ ] Sin errores críticos.

---

**Estado final: DONE ✅**
